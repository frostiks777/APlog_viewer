# Подсвечивать все совпадения поиска в загруженном буфере

Статус: done

## Цель

Сейчас поиск показывает только текущее совпадение рамкой, поэтому по списку не видно, где
ещё есть `ERROR`. Нужно помечать все строки буфера, совпавшие с текущим запросом, отдельным
маркером, не мешая подсветке правил и фильтрам, и не вешать интерфейс на патологическом regex.

## Acceptance Criteria

- [x] Все строки загруженного буфера, совпавшие с запросом поиска, получают маркер (жёлтая
      полоса слева и жёлтая точка на линейке); маркер виден и при активной подсветке правил,
      и при включённом фильтре.
- [x] Подсветка появляется сразу при вводе запроса, без `Enter`; очистка запроса (`Escape`
      или `×`) убирает все маркеры.
- [x] Текущее совпадение отличается от остальных: у него остаётся рамка, и оно тоже входит
      в число помеченных.
- [x] Маркеры привязаны к байтовым смещениям, поэтому tail-append не сдвигает их на соседние
      строки; после догрузки новой страницы маркеры пересчитываются для неё.
- [x] Матчинг совпадений идёт в отдельном Web Worker с бюджетом 400 мс и не делит воркер с
      правилами: зависание одного не отключает подсветку другого. По таймауту маркеры
      выключаются до смены запроса, UI остаётся отзывчивым; проверяется headless-сценарием.
- [x] `npm run typecheck`, `npm run build`, `node scripts/check-search-hits.mjs` зелёные;
      прежние проверки без регрессии.

## План

1. Протокол и воркер совпадений — проверка на фикстуре через браузер.
2. Хук с debounce и бюджетом 400 мс — проверка сценарием таймаута.
3. Маркеры в App и CSS, совмещение с текущим совпадением — проверка скриншотом.
4. Полный чек-чейн, evidence, коммит и пуш.

## Решения

- Отдельный воркер, а не расширение воркера правил: у них разные бюджеты (400 мс у правил и
  у совпадений) и разные виновники. Если положить поиск в воркер правил, зависший запрос
  убьёт и подсветку правил, и фильтры; отдельный воркер изолирует отказ.
- Маркер — `box-shadow` и цвет точки, а не `background`: цвет строки задаётся inline-стилем
  правила, и CSS-фон всё равно был бы перекрыт.
- Совпадения считаются по всему буферу (до 60 000 строк), а не по видимому окну: иначе при
  прокрутке маркеры появлялись бы рывками. Объём тот же, что уже отправляет воркер правил.
- После таймаута подсветка совпадений выключается для текущей пары «запрос + флаги» и
  включается снова при любом изменении запроса. Иначе каждый tail-append снова запускал бы
  зависающий regex.
- Пустой запрос не запускает воркер и не оставляет старых маркеров.

## Handoff

- Выполнено: отдельный воркер подсветки совпадений с бюджетом 400 мс; маркеры по байтовым
  смещениям (полоса слева + жёлтая точка), текущее совпадение с рамкой, предупреждение об
  отключении после таймаута, пересчёт на tail-append и после догрузки страницы.
- Следующий конкретный шаг: настройка цвета маркера в профиле или подсветка совпадений в
  неактивных вкладках — отдельная задача.
- Непроверено / внешний блокер: буфер 60 000 строк с регулярным выражением, близким к
  бюджету; поведение при двух вкладках с разными запросами одновременно.
- Ветка и файлы текущей задачи: `main`, `web/src/search/hits.*`, `useSearchHits.ts`,
  `web/src/App.tsx`, `web/src/styles.css`, `scripts/check-search-hits.mjs`.
