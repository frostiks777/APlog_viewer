# Показать точные номера строк и перейти к строке

Статус: done

## Цель

Сейчас линейка показывает точки по позиции в буфере, а не номер строки в файле: найденную
строку нельзя назвать в тикете. Нужен разреженный индекс (каждые 1024 строки), точные номера
в линейке и переход к строке N (`Ctrl+G`), с фоновой достройкой, кэшем на диске и честным
`·`, пока индекс не покрывает буфер.

## Acceptance Criteria

- [x] В линейке видны точные номера строк файла для загруженного буфера, когда индекс покрывает
      его первую строку; иначе `·`, без выдуманных приближений.
- [x] Индекс разреженный: начало строки 1, 1025, 2049…; кэш в `.aplog/cache` по
      `identity + encoding`, переиспользуется после перезапуска и переживает переименование
      файла (тот же `dev:ino`), сбрасывается при ротации, усечении и смене кодировки.
- [x] Индекс строится в фоне и не блокирует страницы: `POST /line-index` запускает,
      `GET /line-index` отдаёт прогресс; в статусе видно «индекс N%».
- [x] После дописывания файла индекс продолжается с последнего места, а не строится заново;
      номера tail-строк остаются точными.
- [x] `Ctrl+G` (или поле «строка») переходит к строке N, если она в индексе; иначе сообщает,
      сколько строк уже известно, и продолжает построение.
- [x] Фильтры не меняют номера: скрытые строки сохраняют свои номера, видимые показывают
      номер в файле, а не позицию в списке.
- [x] `check-lines.mjs` (API) и `check-lines-ui.mjs` (браузер) зелёные; прежние проверки без
      регрессии; `typecheck` и `build` зелёные.

## Затронутые файлы

- `server/src/files/lineIndex.ts` — разреженный индекс, кэш, достройка, поиск строки/смещения.
- `server/src/files/reader.ts` — `readLastPage` делает `refresh(true)`, чтобы «в конец» видел
  только что дописанные строки; поведение остальных чтений не меняется.
- `server/src/api/routes.ts` — `/line-index`, `/line-number`, `/line-offset`, `firstLine` у
  страниц; индексные маршруты не держат хэндл пула, чтобы не мешать ротации.
- `server/src/config.ts` — шаг индекса, размер порции, частота сохранения кэша.
- `web/src/api.ts` — типы статуса и методы.
- `web/src/App.tsx` — `lineBase`, линейка с номерами, `Ctrl+G`, опрос индекса, статус.
- `web/src/styles.css` — колонка номера строки и поле перехода.
- `scripts/check-lines.mjs`, `scripts/check-lines-ui.mjs` — сценарии.

1. Индекс: постройка, кэш, `lineNumberAt`, `offsetForLine`, достройка — проверка
   `check-lines.mjs`.
2. API: статус/запуск, `firstLine` у `page` и `last-page` — проверка API.

5. Полный чек-чейн, evidence, коммит и пуш.

## Решения

- Шаг 1024 строки: поиск номера читает не больше ~1024 строк от ближайшей засечки, а не файл
  целиком. Для 13-МБ лога это доли секунды, для 6 ГБ — предсказуемо.
- Кэш именуется хэшем `identity + encoding`, путь хранится внутри для отладки. Поэтому
  `portal.log -> portal.0.log` не теряет индекс, а новый файл с другим `dev:ino` — новый кэш.
- Индекс — снимок до текущего EOF. При дописывании он **продолжается** с сохранённого
  `size`, а не пересчитывается: `endsWithNewline` говорит, началась ли новая строка или
  продолжилась последняя.
- Build идёт в главном потоке, но асинхронными окнами по 1 МБ; regex нет, поэтому вотчдог не
  нужен. Каждые 32 МБ состояние пишется в кэш, чтобы перезапуск не начинал с нуля.
- `firstLine` считается только для `page` и `last-page`: tail продолжает нумерацию клиента,
  `page-before` вычитает число строк. Это убирает лишнее чтение на каждом tail-тике.
- Номера строк не зависят от фильтра: номер ищется двоичным поиском по полному буферу,
  а не по позиции в видимом списке.
- Пока индекс не покрывает первую строку буфера, показываем `·`; приближение «примерно
  строка N» запрещено.

## Handoff

- Выполнено: разреженный индекс строк с шагом 1024 и кэшем по `dev:ino + encoding`;
  фоновая достройка окнами 1 МБ; `firstLine` у `page`/`last-page`; `line-number` и
  `line-offset`; номер в линейке с `·` до покрытия; `Ctrl+G` и поле «строка»; прогресс
  «индекс N%»; нумерация не зависит от фильтра и переживает append, prepend и tail.
- Следующий конкретный шаг: отмена/пауза построения индекса для гигабайтных файлов и GC
  кэша по `lastUsed` — отдельная задача; затем автозапуск/single-instance или экспорт.
- Непроверено / внешний блокер: реальный файл 6 ГБ (время сборки и p95 перехода к строке);
  ротация во время активной сборки индекса (защита `generation` есть, live-сценарий нет);
  переименование файла при живом сервере.
- Ветка и файлы текущей задачи: `main`, `server/src/files/lineIndex.ts`,
  `server/src/files/reader.ts`, `server/src/api/routes.ts`, `server/src/config.ts`,
  `web/src/api.ts`, `web/src/App.tsx`, `web/src/styles.css`, `scripts/check-lines*.mjs`.
