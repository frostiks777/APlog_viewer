# Собрать дашборд просмотра логов APlog Viewer

Статус: in-progress

## Цель

Локальное веб-приложение для одного пользователя: читает текстовые логи прямо с сетевых
шаров (`\\<host>\<share>\...`) без маппинга дисков, показывает их в браузере с подсветкой
по настраиваемым правилам, фильтрацией, поиском, tail-режимом и сохранением рабочего
пространства. Референс функциональности — UVviewsoft LogViewer, но профиль хранит не
только вкладки, а все настройки. Backend отдаёт стабильный API для будущего агента.

## Acceptance Criteria

Производительность измеряется на зафиксированном стенде (Windows 11, Node 26.13, SMB-шара
в корпоративной сети, холодный и тёплый кэш раздельно), p95 по ≥30 повторам. Пока это
гипотезы: замеры ниже — единичные, не p95.

- [ ] Локальный сервер на `127.0.0.1:7801` читает `\\<host>\c$\...` без маппинга сетевого
      диска; production-сборка отдаёт UI и API с одного origin, без Vite.
- [ ] Файл 30 МБ: первое видимое окно p95 ≤ 300 мс после готовности backend (запуск
      браузера и первая аутентификация SMB измеряются отдельно).
- [ ] Файл 1 ГБ открывается позиционным чтением без полного скана; память backend-процесса
      < 300 МБ при 3 вкладках, одном поиске и tail (браузер учитывается отдельно).
- [ ] При открытии вкладки показывается конец файла; переход в любую точку по byte offset
      без полного скана; кнопки «в начало»/«в конец».
- [ ] Точные номера строк выдаются только для проиндексированного префикса; вне его номер
      неизвестен, а переход к строке N запускает отменяемую индексацию с прогрессом.
- [ ] Разреженный индекс кэшируется на диске, ключ — `identity` (`dev:ino`) + `generation`;
      rename при ротации сохраняет индекс, truncate/replace сбрасывает.
- [ ] Кэш чистится по `lastUsed` (7 дней) с мягким лимитом: при достижении лимита новые
      индексы не создаются, а не удаляются закреплённые.
- [ ] Tail: завершённая строка видна p95 ≤ 2 с от момента, когда она стала доступна
      читающему клиенту; события `append`/`rotated`/`truncated` различаются.
- [ ] Поиск: построчный regex (JS-диалект, без многострочности), фиксированный диапазон
      `[startByte, endByte)`, вперёд и назад; 100 МБ ≤ 5 с на согласованном корпусе; отмена
      подтверждается ≤ 500 мс; опасный паттерн не блокирует UI/API.
- [ ] Правила подсветки: подстрока или regex, цвет текста и фона, регистр, инверсия,
      вкл/выкл, приоритет, привязка к вкладке; правило с ошибкой regex отключается с
      предупреждением, а не ломает рендер.
- [ ] Фильтры include/exclude: `visible = (нет include ИЛИ совпал include) И НЕ exclude`;
      скрытие работает в загруженном буфере и помечается как неполный просмотр.
- [ ] Экспорт фиксирует `generation`, `endByte` и версию правил; потоковый, UTF-8;
      отменённый/неполный результат помечается.
- [ ] Профиль восстанавливает вкладки, пути и подписи, кодировку каждого файла, правила,
      фильтры, шрифт, размеры внутренних панелей и byte anchor; недоступный файл не ломает
      восстановление остальных. Геометрия OS-окна браузера не обещается.
- [ ] Кодировки: BOM (UTF-8/UTF-16LE/BE), UTF-8, cp1251, cp866, UTF-16LE/BE; автоопределение
      с показом основания и ручной override на вкладку.
- [ ] API v1: opaque `fileId`, `generation`, курсоры, машинные коды ошибок, лимиты окна,
      runtime-валидация; OpenAPI-схема пригодна для внешнего агента.
- [ ] `/stats` в MVP отсутствует: агрегаты требуют парсера событий и вынесены в отдельную
      задачу (кандидат — NDJSON `StdioProcessor.log.json`).
- [ ] Автозапуск: задача Task Scheduler в интерактивном контексте пользователя; отключение
      удаляет задачу, а не только флаг в профиле; single-instance.
- [ ] Все пользовательские строки — русские; `.agents/shared/checks.md` заполнен реальными
      командами и зелёный.

## Решения

- Форма поставки — локальное веб-приложение: backend на машине пользователя, UI в браузере
  (`127.0.0.1:7801`). Браузер не читает SMB, поэтому чтение шары — только на backend.
- Backend — Node.js + TypeScript (Fastify), фронт — React + Vite + TS: один язык, один
  тулчейн.
- Чтение — позиционные окна по 64 КБ без mmap. Скроллбар по байтам, не по строкам.
- Идентичность файла — `sourceId` (запись профиля) + `identity` (`dev:ino`) + `generation`
  (эпоха содержимого). Ночная ротация сохраняет индекс, truncate/replace сбрасывает.
- Tail — polling по размеру и идентичности; хендл открывается на один опрос и сразу
  закрывается, иначе ротация на шаре падает у писателя с `EPERM` (проверено).
- Кодировки и границы строк — часть ядра: UTF-16 режется по двухбайтовому переводу, BOM
  снимается с текста, последняя строка без перевода считается строкой.
- Regex — построчный, JS-диалект; поиск в worker с бюджетом, правило с ошибкой отключается.
- Локальный API защищён Host/Origin-allowlist и отсутствием CORS; токен — вместе с сетевым
  доступом.
- Автообновление отдельной вкладки не переключает активную вкладку.
- Задачи ведутся в `tasks/` по скиллу `task-file` (формат idm_main), а не в `ai/tasks/`.

## Разбор архитектурного аудита (APlog_Viewer_review.md)

Вердикты: «принято» — меняем план/код; «принято частично» — берём суть, отказываемся от
формы; «отклонено» — с обоснованием.

| ID | Вердикт | Что сделано или запланировано | Обоснование отказа |
|---|---|---|---|
| F01 identity ≠ версия содержимого | Принято | `sourceId` + `identity` (`dev:ino`) + `generation`; события `rotated`/`truncated`; в манифест индекса пойдут `generation`, `scannedBytes`, кодировка, версия формата | — |
| F01 fallback-отпечаток как доказательство | Принято | `path+size+mtime` остаётся только эвристикой с пометкой `trust: weak`; решение «только дописывание до ротации» зафиксировано в ADR | — |
| F02 жизненный цикл tail | Принято частично | Реализованы `append`/`rotated`/`truncated` и чтение с начала при смене поколения. В план: `disconnected`/`access_denied` с backoff и перепроверкой identity после восстановления | Отдельный режим follow-handle не нужен: вкладка следует пути, как в LogViewer |
| F03 номер строки ≠ byte offset | Принято | Точные номера только в проиндексированном префиксе, `indexComplete`, отменяемая индексация; сейчас номера заменены линейкой-точками по просьбе владельца | — |
| F03 длинные строки и wrap | Принято | Лимит байтового окна 8 МБ, частичная строка будет помечаться; wrap по умолчанию выключен | — |
| F04 декодер и разделитель строк — ядро | Принято, реализовано | UTF-16LE/BE режется по двухбайтовому переводу, BOM снимается, CRLF/LF, последняя строка без перевода; `scripts/check-encodings.mjs` — 4/4 PASS | — |
| F04 автоопределение — гипотеза | Принято | Кодировка видна в UI и переопределяется на вкладку; основание выбора будет показываться | — |
| F05 семантика regex | Принято | Построчный regex, JS-диалект, один matcher для подсветки/поиска/фильтра; многострочность — отдельная задача | — |
| F05 RE2 | Отклонено | Вместо RE2 — worker с бюджетом времени, отменой и автоотключением правила | RE2 теряет look-around/backreferences и требует нативной сборки под Windows; корпус и авторские паттерны этого не требуют |
| F05 regex в UI-потоке | Принято | Подсветка ограничится видимыми строками + бюджет на правило; поиск уходит в worker | — |
| F06 фильтрация меняет модель прокрутки | Принято частично | Скрытие в загруженном буфере с явной пометкой «неполный просмотр»; экспорт фиксирует `generation`+`endByte`; навигация по совпадениям — отдельная задача | Полный индекс результатов фильтра — второй индекс и вторая модель прокрутки; для MVP избыточно |
| F07 общий бюджет ресурсов | Принято частично | Лимит одновременных чтений, один tail-опрос на файл, ограничение буферов | Отдельный helper-процесс для SMB отклонён в MVP: один пользователь и ≤5 вкладок, риск снимается лимитом конкурентности; вернёмся после теста с обрывом шары |
| F08 числа не SLA | Принято | AC переписаны: p95, стенд, cold/warm, память backend отдельно от браузера | — |
| F09 защита на loopback | Принято частично | Host/Origin-allowlist (проверено: чужой Host → 403), CORS не разрешён, рендер только текстом | Токен отклонён для localhost: не защищает от процесса того же пользователя и добавляет трение; включим с сетевым доступом |
| F09 opaque fileId и allowlist корней | Принято частично | Вкладки уже адресуются внутренним `tabId`, путь передаётся только при регистрации | Жёсткий allowlist корней отклонён в MVP: пользователь и так имеет доступ ко всем этим файлам, а браузерный вектор закрыт Origin |
| F10 автозапуск и контекст | Принято | В план: Task Scheduler, интерактивный токен, абсолютные пути, single-instance, disable = удаление задачи | — |
| F11 геометрия окна браузера | Принято | Из обязательств убрана; сохраняются панели, шрифт, byte anchor | — |
| F12 API до reader/UI | Принято частично | Контракт фиксируется сейчас: `generation`, курсоры, коды ошибок, лимиты, валидация, OpenAPI | Reader уже написан и работает; откатывать его ради «API вперёд» дороже, чем зафиксировать контракт поверх (изменения локальны в `routes.ts`) |
| F13 агрегаты требуют парсера | Принято | `/stats` убран из MVP AC; кандидат — NDJSON-сайдкар, отдельная задача | — |
| F14 SSE и восстановление | Принято | Tail остаётся на polling (идемпотентен по offset); если появится SSE — один канал с `resync_required` | — |
| F15 профиль ≠ кэш | Принято | Каталоги раздельные, `.bak`, повтор на EPERM/EBUSY, версия схемы; GC по `lastUsed` — в план | — |
| F16 production и доказательства | Принято частично | Production-сборка с одного origin реализована, lockfile есть, скриншот и воспроизводимые скрипты — в Evidence; single-instance — в план | — |

## Handoff

- Выполнено: каркас, чтение шары, кодировки, виртуализованный UI, открытие в конце файла,
  линейка-точки, tail с событиями ротации, Host/Origin-защита, бэкап профиля; разобран
  архитектурный аудит (см. таблицу выше).
- Следующий конкретный шаг: индекс строк (`identity`+`generation`, GC по `lastUsed`),
  затем поиск в worker.
- Непроверенные гипотезы (не «нет»): поведение `dev:ino` на конкретном SMB-сервере при
  переподключении; блокировка файла писателем во время чтения; поведение при обрыве сети;
  доступ из Task Scheduler под тем же пользователем; p95-замеры на целевом стенде;
  поведение антивируса при частой записи профиля.
- Ветка и файлы текущей задачи: `main`, `tasks/2026-11-13-aplog-viewer-mvp/task.md`.
