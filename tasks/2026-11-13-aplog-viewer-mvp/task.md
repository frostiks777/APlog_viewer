# Собрать дашборд просмотра логов APlog Viewer

Статус: in-progress

## Цель

Локальное веб-приложение для одного пользователя: читает текстовые логи прямо с сетевых
шаров (`\\<host>\<share>\...`) без маппинга дисков, показывает их в браузере с подсветкой
по настраиваемым правилам, фильтрацией, поиском, tail-режимом и сохранением рабочего
пространства. Референс функциональности — UVviewsoft LogViewer, но сессия должна хранить
не только вкладки, а все настройки. Backend дополнительно отдаёт стабильный API для
будущего агента и ML-аналитики.

## Acceptance Criteria

- [ ] Локальный сервер на `127.0.0.1:7801` читает `\\<host>\c$\...` без маппинга сетевого
      диска; браузер открывает UI автоматически.
- [ ] Файл 30 МБ открывается до 300 мс; 1 ГБ — без чтения целиком (RSS процесса < 300 МБ),
      прокрутка в любую точку файла по байтовому offset без полного скана.
- [ ] Разреженный индекс строк: номер строки и переход к строке N; индекс кэшируется на
      диске и переживает ночную ротацию файла (rename сохраняет `dev:ino`).
- [ ] Кэш индекса чистится: записи старше 7 дней удаляются, общий размер ограничен,
      чистка не трогает индексы файлов, открытых в текущей сессии.
- [ ] Tail-режим: новые строки появляются не позже 2 с после записи, follow tail
      переключается на вкладку.
- [ ] Поиск подстрокой и regex, вперёд/назад, по всему файлу, отменяемый, с прогрессом;
      поиск по 100 МБ укладывается в 5 с.
- [ ] Правила подсветки: подстрока или regex, цвет текста и фона, учёт регистра, инверсия,
      вкл/выкл, приоритет, привязка к вкладке или к профилю.
- [ ] Фильтры include/exclude по подстроке и regex скрывают строки; есть экспорт
      отфильтрованного результата в файл.
- [ ] Профиль (JSON) сохраняет вкладки, пути и подписи, кодировку каждого файла, правила,
      фильтры, шрифт, геометрию окна и позицию; после перезапуска состояние восстанавливается.
- [ ] Кодировки: автоопределение (BOM, валидный UTF-8, fallback cp1251/cp866) и ручной
      выбор на вкладку, выбор запоминается для файла.
- [ ] API v1 с OpenAPI-схемой: окно строк, поиск, tail, список файлов, агрегаты по
      уровню/источнику/времени — пригодно для внешнего агента и ML.
- [ ] Автозапуск ставится и снимается командой; при выключенном автозапуске приложение
      не стартует само.
- [ ] Все пользовательские строки — русские; `checks.md` заполнен реальными командами и
      зелёный.

## План

1. Каркас: npm-workspace `server` + `web`, Fastify на `127.0.0.1`, Vite-прокси, health-check.
   Проверка: `npm run dev` поднимает оба, `curl /api/v1/health` → 200.
2. Чтение файла: профиль с одним путём на шаре, окно строк по byte offset, автоопределение
   кодировки, отдача JSON. Проверка: `curl` окна на реальном логе, кириллица не ломается.
3. UI-просмотр: вкладки, виртуализованный список, скролл по байтам, счётчик строк.
   Проверка: скриншот + прокрутка 30 МБ файла без фризов.
4. Индекс строк и кэш: разреженный индекс, `dev:ino`, sidecar в профиле, переход к строке,
   GC по возрасту и размеру. Проверка: unit-тест на ротацию (rename) и на GC.
5. Tail: polling, SSE, follow tail, индикатор новых строк. Проверка: дописать строку в
   файл → она появляется в UI ≤2 с.
6. Поиск: подстрока и regex вперёд/назад, SSE-прогресс, отмена, переход к хиту.
   Проверка: бенчмарк на 100 МБ, отмена посреди прогона.
7. Правила и фильтры: движок, панель управления, приоритеты, привязка к вкладке,
   экспорт отфильтрованного файла. Проверка: скриншот раскраски + дифф экспорта.
8. Профиль: сохранение и восстановление вкладок, кодировок, правил, геометрии; миграция
   версии; атомарная запись. Проверка: перезапуск процесса → состояние идентично.
9. API v1: OpenAPI, `/files`, `/window`, `/search`, `/tail`, `/stats`; схема пригодна для
   внешнего агента. Проверка: `curl` каждого эндпоинта + валидная OpenAPI-схема.
10. Автозапуск: install/uninstall скрипты Task Scheduler, флаг в профиле, проверка
    включения и выключения. Проверка: `schtasks /query` до и после.
11. Финализация: заполнить `.agents/shared/checks.md`, прогнать чек-чейн, ADR, README.
    Проверка: `npm run verify` зелёный, evidence заполнен.

## Решения

- Форма поставки — локальное веб-приложение: backend на машине пользователя, UI в браузере
  (`127.0.0.1`). Браузер не умеет читать SMB, поэтому чтение шары — только на backend.
- Backend — Node.js + TypeScript (Fastify): один язык с фронтом, позиционное чтение
  `FileHandle.read(buffer, 0, length, position)` даёт экономию памяти как у Lister без
  mmap, который по SMB ведёт себя непредсказуемо при обрыве.
- Фронтенд — React + Vite + TypeScript: виртуализованный список строк, зрелая экосистема.
- Большие файлы — техника Total Commander Lister: в памяти только окно (~256 КБ),
  скроллбар по байтовому offset, поиск чанками. Отличие: Lister принципиально не показывает
  номера строк, потому что для этого нужен полный скан; мы добавляем разреженный индекс
  (каждые N строк) с кэшем на диске.
- Кэш индекса — в папке профиля, ключ `dev:ino` (NTFS File ID + серийник тома), поэтому
  ночная ротация `portal.log → portal.0.log` не инвалидирует индекс. Fallback при
  недоступной идентичности — `path+size+mtime` плюс отпечаток первых/последних 4 КБ.
- GC кэша: возраст > 7 дней и общий лимит с LRU-вытеснением; индексы открытых вкладок
  не удаляются.
- Автообновление — polling `mtime` раз в 1–2 с: SMB не даёт надёжных событий ФС.
- Параметры на вкладку, а не только глобально: кодировка, tail, wrap — как в LogViewer.
- API v1 — публичный контракт с OpenAPI: его же использует UI, поэтому агент и ML получают
  те же окна, поиск, tail и агрегаты без отдельного слоя.
- Доступ: слушаем `127.0.0.1` без пароля; слой аутентификации закладывается в конфиг
  (`auth: none | token`) и включается, когда появится сетевой доступ.
- Автозапуск — Task Scheduler, устанавливается и снимается скриптами; флаг в профиле
  позволяет отключить без удаления задачи.
- Задачи ведутся в `tasks/` по скиллу `task-file` (формат idm_main), а не в `ai/tasks/`.

## Handoff

- Выполнено: интервью и анализ референса; шаги 1–3 и 5 плана — каркас workspace,
  Fastify-сервер, чтение окна строк с шары, автоопределение кодировки, виртуализованный
  UI, tail-опрос. Проверки и цифры — в Evidence.
- Следующий конкретный шаг: шаг 4 — разреженный индекс строк и кэш `dev:ino` с GC.
- Непроверено / внешний блокер: правила подсветки применяются на клиенте, панели
  управления правилами и фильтрами ещё нет; поиск, экспорт, автозапуск и OpenAPI — впереди.
- Ветка и файлы текущей задачи: `main`, `tasks/2026-11-13-aplog-viewer-mvp/task.md`.

## Зависимости

- Доступ пользователя Windows к административным шарам `\\<host>\c$` (проверено чтением).
- Node.js 26 и npm 11 на машине (проверено).
- Права на создание задачи в Task Scheduler для автозапуска.

## Follow-ups

- `StdioProcessor.log.json` (NDJSON-дубль лога) — потенциальный источник структурированных
  событий для панели «по уровню/источнику»; в MVP не используется.
- Скиллы харнесса `process-inbox`, `perform-task`, `continue` ссылаются на `ai/tasks/` и в
  этом репозитории не применяются — при обновлении харнесса проверить, не конфликтует ли.
- Часть русских текстов в скиллах харнесса пришла с испорченной кодировкой (`????`) —
  к нашему коду отношения не имеет, но при апстрим-обновлении стоит сверить.
