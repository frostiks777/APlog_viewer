# Сделать правила подсветки и фильтры управляемыми из интерфейса

Статус: done

## Цель

Правила подсветки и include/exclude-фильтры уже есть в модели профиля, но правятся только
руками в `.aplog/profile.json`, а фильтры вообще не влияют на показ. Нужна выдвижная панель
справа: создание, редактирование, приоритет и область действия правил, живое превью на логе,
фильтрация буфера с автодогрузкой и защита от регулярного выражения, которое вешает браузер.

## Acceptance Criteria

- [x] Панель «Правила» открывается кнопкой в тулбаре, содержит вкладки «Подсветка» и
      «Фильтры»; открытость, ширина и активная вкладка сохраняются в профиле и
      восстанавливаются после перезагрузки страницы.
- [x] Правило: вкл/выкл, подстрока или regex, регистр, цвет текста и фона (или «нет»),
      жирность, область «все вкладки / только эта», порядок вверх/вниз, удаление, создание.
      Изменения видны на логе сразу и сохраняются в `profile.json` через 600 мс без кнопки.
- [x] Приоритет: при пересечении правил применяется первое в списке (больший `priority`);
      проверяется юнит-сценарием на чистой функции.
- [x] Область действия: правило с `tabId` применяется только к своей вкладке, глобальное —
      ко всем; проверяется юнит-сценарием.
- [x] Битый regex не ломает ничего: правило помечается «ошибка в выражении», не применяется,
      остальные продолжают работать; `PUT /api/v1/rules` отвечает 200 и сохраняет текст,
      а не 400 — иначе автосейв терял бы ввод на середине паттерна.
- [x] Патологический regex не вешает UI: матчинг идёт в Web Worker, по таймауту 400 мс воркер
      убивается, правило получает `disabledReason: 'timeout'`, сохраняется в профиль и больше
      не применяется до явного «включить снова»; проверяется headless-сценарием с `(a+)+$`.
- [x] Фильтр: `visible = (нет include ИЛИ совпал include) И НЕ exclude`; проверяется
      юнит-сценарием. Скрытие работает по буферу, счётчик «показано M из N» в статусе.
- [x] При активном фильтре буфер автоматически догружается вверх, пока не наберётся экран
      совпадений, не достигнут лимит 20 000 строк или начало файла; есть пауза/продолжение.
- [x] Позиция прокрутки сохраняется в `scrollOffset` (сейчас поле есть, но UI его не пишет);
      вкладка без tail открывается на сохранённой позиции.
- [x] `web/src/api.ts` не содержит мёртвого `showLineNumbers`, которого нет на сервере.
- [x] `npm run typecheck`, `npm run build`, `node scripts/check-encodings.mjs`,
      `node scripts/check-rotation.mjs`, `node scripts/check-rules.mjs` зелёные.

## Решения

- Панель справа, выдвижная; ширина и вкладка — в `ui.panels`. Модалка закрывала бы лог,
  а живое превью — главная причина вообще открывать панель.
- Правила глобальные и на вкладку (модель `scope`/`tabId` уже была).
- Фильтр работает по буферу с автодогрузкой до 20 000 строк: полноценный скан файла — это
  поиск со своим бюджетом, отдельная задача. Автодогрузка даёт «увидеть последние ERROR»
  без ожидания полного прохода.
- Автосейв с debounce 600 мс. Защита от плохого ввода — три уровня: синтаксис regex
  проверяется компилятором и показывается бейджем; матчинг вынесен в Worker, поэтому
  катастрофический бэктрекинг убивается `terminate()`; правило-виновник сохраняется с
  `disabledReason: 'timeout'`, иначе после перезагрузки страница снова зависла бы на нём.
- Пустое выражение включённого правила не ограничивает показ (иначе фильтр «выключил бы всё»
  в момент, когда пользователь стёр паттерн).
- Цвета: нативный `<input type="color">` + отдельный сброс в «нет»; сервер нормализует
  к `#rrggbb` или `transparent`, ручной ввод hex пока не нужен.
- `PUT /rules` принимает любое выражение и возвращает `issues`; 400 был бы несовместим с
  автосейвом.

## Handoff

- Выполнено: панель правил и фильтров с автосейвом, worker-матчинг с бюджетом 400 мс и
  сохранением `disabledReason`, фильтрация буфера по смещениям с автодогрузкой, счётчики,
  позиция чтения в профиле, пять воспроизводимых проверок.
- Следующий конкретный шаг: поиск по файлу в том же worker-пуле — тот же бюджет времени,
  навигация вперёд/назад по byte offset.
- Непроверено / внешний блокер: реальный REDOS на длинных строках production-логов (фикстура
  36 символов); автодогрузка до 20 000 строк по SMB (в проверках локальный файл); поведение
  панели при 50+ правилах (виртуализации в панели нет).
- Ветка и файлы текущей задачи: `main`, `web/src/rules/`, `web/src/RulesPanel.tsx`,
  `web/src/App.tsx`, `server/src/api/routes.ts`, `server/src/profile/store.ts`,
  `scripts/check-rules*.mjs`, `scripts/check-filter.mjs`, `scripts/check-panel.mjs`.
