# Устранить гонку открытия файла и утечку FileHandle

Статус: done

## Цель

Сервер иногда падает с `ERR_INVALID_STATE: A FileHandle object was closed during garbage
collection` и перестаёт отвечать на `127.0.0.1:7801`. Причина — два одновременных запроса
к одному пути открывают файл дважды; второй результат перезаписывает первый в кэше пула,
и первый `FileHandle` становится недостижимым без `close()`. Нужно открывать файл один раз
на путь и закрывать хэндл, если открытие не удалось.

- [x] Если `stat` или автоопределение кодировки падает после `open`, хэндл закрывается,
      а ошибка пробрасывается вызывающему.
- [x] `node scripts/check-pool.mjs` проверяет дедупликацию, кэш, повторное открытие после

- [x] Сервер переживает одновременные `last-page` и `tail` на холодном пути и остаётся
      доступным; ручная проверка `/api/v1/health` после сценария.
- [x] `npm run typecheck`, `npm run build`, прежние проверки без регрессии.

## Решения

- Кэшируем **промис** открытия, а не только результат: второй запрос ждёт первое открытие и
  получает тот же экземпляр. Это дешевле блокировки и не создаёт очереди.
- `LogFile.open` сначала открывает хэндл, затем делает `stat` и определяет кодировку; при
  любой ошибке закрывает хэндл в `catch`. Иначе Node 26 считает незакрытый `FileHandle`
  ошибкой уже на сборке мусора.
- `release` во время открытия не трогает `opening`: после завершения файл попадёт в кэш и
  будет закрыт по простою. Это не утечка — пул продолжает владеть хэндлом.

## Handoff

- Выполнено: дедупликация одновременных открытий через `opening: Map<path, Promise<LogFile>>`;
  `LogFile.open` закрывает хэндл, если `stat`/автодетект упали после `open`; сценарий пула.
- Следующий конкретный шаг: учесть активные чтения в `closeIdle` (см. follow-up), затем
  вернуться к фиче подсветки совпадений.
- Непроверено / внешний блокер: длительное чтение > 60 с и закрытие по простою; поведение при
  обрыве SMB между `open` и `stat`.
- Ветка и файлы текущей задачи: `main`, `server/src/files/reader.ts`,
  `scripts/check-pool.mjs`.
