# Добавить поиск по файлу с навигацией вперёд и назад

Статус: done

## Цель

Сейчас найти `ERROR` в 13-МБ логе можно только глазами: фильтр работает по загруженному
буферу и не ищет по всему файлу. Нужен поиск по подстроке или regex через весь файл, с
переходом к совпадению по байтовому смещению, навигацией вперёд/назад (`Enter`, `F3`,
`Shift+F3`) и защитой от регулярного выражения, которое вешает матчинг.

## Acceptance Criteria

- [x] В панели над логом есть поле запроса, переключатели «regex» и «регистр», кнопки
      «назад/вперёд»; состояние переключателей сохраняется в `ui.search` профиля.
- [x] `POST /api/v1/tabs/:id/search` ищет по всему файлу, а не по буферу; направление
      `forward`/`backward`, `fromOffset`, лимит совпадений; ответ содержит `offset`,
      `endOffset`, `text`, `cursor`, `eof`, `scannedBytes`, `timedOut`.
- [x] Переход к совпадению вне загруженного буфера догружает страницу с этой строкой; текущее
      совпадение подсвечивается рамкой и не скрывается активным фильтром.
- [x] `Enter`/`F3` — следующее совпадение, `Shift+Enter`/`Shift+F3` — предыдущее; счётчик
      показывает позицию и число найденных; повторный поиск не пересканирует уже найденное.
- [x] Поиск не блокирует сервер: матчинг идёт в `worker_threads`, по бюджету 5 с воркер
      убивается, ответ приходит с `timedOut: true`, а не подвешивает API.
- [x] Битый regex возвращает 400 с текстом ошибки, пустой запрос — 400; остальные запросы
      работают.
- [x] Поиск учитывает кодировку вкладки (проверка на cp1251), включая ручной override.
- [x] `npm run typecheck`, `npm run build`, `node scripts/check-search.mjs`,
      `node scripts/check-search-ui.mjs` зелёные; прежние проверки без регрессии.

2. Протокол и воркер поиска: forward/backward окнами, прогресс, лимиты — проверка

3. Раннер с таймаутом и роут — проверка битого regex, пустого запроса и `timedOut`.
4. `ui.search` в профиле и клиентские типы — проверка `PATCH /ui` и `typecheck`.
5. Хук сессии и панель в UI — проверка `check-search-ui.mjs` и скриншот.
6. Полный чек-чейн, evidence, коммит и пуш.

## Решения

- Поиск по всему файлу выполняет сервер: браузер не должен вычитывать гигабайты через HTTP.
  Наружу отдаются только совпадения и курсор.
- Матчинг в `worker_threads`, а не в главном потоке Fastify: катастрофический бэктрекинг
  нельзя прервать из того же потока. Бюджет 5 с, затем `terminate()` и `timedOut: true`.
  Воркер шлёт прогресс, поэтому по таймауту возвращаются уже найденные совпадения.
- Курсор всегда указывает на начало строки: вперёд — на строку после последнего
  просмотренного места, назад — на самое раннее найденное совпадение. Так `F3` не находит
  одно и то же дважды.
- Назад сканируем окно до 16 МБ перед курсором, а не весь файл: поиск назад не должен
  читать 6 ГБ. Если совпадений нет, следующее нажатие продолжает с курсора.
- Лимит совпадений на запрос 200: больше в панель не влезает, а курсор позволяет продолжить.
- Пустой запрос — 400: это действие пользователя, а не автосейв, терять нечего.
- Ошибка синтаксиса regex — 400 с текстом: в отличие от правил, поиск не сохраняет ввод
  на каждый символ, поэтому молчаливое `issues` здесь только запутает.

## Handoff

- Выполнено: поиск по всему файлу через серверный `worker_threads` с бюджетом 5 с; курсоры
  вперёд/назад, кэш совпадений на клиенте, переходы с догрузкой страницы, `Enter`/`F3`/
  `Shift+F3`/`Ctrl+F`, счётчик и сохранение флагов в `ui.search`; две воспроизводимые проверки.
- Следующий конкретный шаг: подсветка всех найденных строк в буфере (сейчас только текущее
  совпадение) — отдельная задача, чтобы не смешивать её с навигацией.
- Непроверено / внешний блокер: поиск на файле 6 ГБ и по SMB-шаре (в проверках локальный
  файл); строка длиннее 16 МБ (защита от зацикливания есть, корректность разрыва не
  тестировалась); два одновременных поиска из разных вкладок.
- Ветка и файлы текущей задачи: `main`, `server/src/files/lines.ts`, `server/src/search/`,
  `server/src/api/routes.ts`, `server/src/profile/store.ts`, `web/src/search/`,
  `web/src/App.tsx`, `web/src/api.ts`, `web/src/styles.css`, `scripts/check-search*.mjs`.
