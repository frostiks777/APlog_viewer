# task-file

Правка одной функции, опечатка или локальный fix идут сразу в код. Всё крупнее получает
файл задачи, чтобы другой агент (или ты через неделю) продолжил без восстановления
контекста.

## Create

1. Скопируй [`tasks/TEMPLATE.md`](../../../tasks/TEMPLATE.md) в
   `tasks/<YYYY-MM-DD>-<slug>/task.md`. Дата — день заведения, slug — kebab-case
   (`2026-11-13-log-tail-render`).
2. Заполни `Цель`, `Acceptance Criteria`, `Затронутые файлы`, `План` до первой строки кода.
   Критерии — проверяемые: команда, сценарий или наблюдаемое поведение. Критериев
   «написать тесты» без предмета проверки не бывает.
3. Незакрытые вопросы интервью — в `Решения` с пометкой «открыто», а не в переписке.

## Run

1. **Resolve** — прочитай файл целиком. Двусмысленный критерий: остановись и спроси.
   Поставь `Статус: in-progress` до первой правки кода.
2. **Implement** — минимальный дифф под критерии (скиллы `plan`, `ponytail`, `tdd`).
   Проблемы рядом с задачей идут в `## Follow-ups`, а не в этот дифф.
3. **Review** — прочитай дифф целиком и пройди по критериям по одному (скилл `code-review`,
   для крупного — `verify`).
4. **Evidence** — отметь каждый критерий `- [x]` и впиши в таблицу `Evidence` чем именно
   доказан: команда, сценарий, ревизия/дата, ограничения. Сборка и runtime — отдельные
   строки. Невыполненную проверку помечай как непроверенную, а не как passed.
5. **Handoff** — заполни `## Handoff`: что сделано, следующий конкретный шаг, что осталось
   непроверенным, ветка и файлы.
6. **Publish** — `.agents/shared/checks.md` зелёный, один PR на задачу, ссылка на
   `task.md` в теле; после мержа `Статус: done`. Файл остаётся историей решения.

Статусы: `todo`, `in-progress`, `blocked`, `done`. Остановленная задача — `blocked` с
указанием, где и почему встала.

## Master plans

План, который не влезает в один PR, делится на дочерние `task.md`, по одному на PR.
Каждый ребёнок несёт только свои критерии, файлы и проверки; агент работает строго в
рамках текущего ребёнка и не расширяет дифф до родительского плана.

## Границы

- `tasks/` — единственное место задач проекта. `ai/tasks/` и `ai/inbox.md` из харнесса в
  этом репозитории не используются; при расхождении правил побеждает этот скилл.
- GitHub Issues — только для внешних багов и запросов, которые приходят не от владельца
  проекта (см. `docs/agents/issue-tracker.md`). Задача владельца живёт в `tasks/`.
