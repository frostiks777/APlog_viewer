# Чек-чейн перед коммитом

Единый источник команд проверок. Используется скиллами `perform-task` и `verify`.

## 1. Установка зависимостей

```bash
npm ci
```

Ставится строго по `package-lock.json`. После `npm install` проверь, что lock-файл
закоммичен: иначе проверки измеряют другую версию.

## 2. Линт + типы

```bash
npm run typecheck
```

TypeScript в strict-режиме, baseline — ноль ошибок. Отдельного линтера пока нет:
форматирование держим по месту, спорные случаи — в code review.

## 3. Сборка

```bash
npm run build
```

`web` собирается Vite, `server` — tsc. Production-сервер отдаёт и API, и статику с одного
origin; Vite в проде не участвует.

## 4. Тесты

Юнит-фреймворка пока нет, поэтому проверки идут сценариями на живом API. Сервер должен быть
запущен (`npm start`) на `127.0.0.1:7801`; все сценарии принимают другим первым аргументом
base URL.

Чтобы не трогать рабочий профиль и открытую вкладку, подними второй экземпляр:

```powershell
$env:APLOG_PORT='7802'; $env:APLOG_PROFILE_DIR='C:\Github\APlog_viewer\.aplog\test-profile'
node server/dist/index.js
```

Дальше передавай `http://127.0.0.1:7802` первым аргументом. Проверки с браузером всё равно
меняют профиль тестового экземпляра и восстанавливают его в `finally`.

```bash
node scripts/check-encodings.mjs
node scripts/check-rotation.mjs
node --expose-gc scripts/check-pool.mjs
```

- `check-encodings.mjs` — UTF-8 BOM, UTF-16LE/BE, cp1251, границы строк, CRLF, последняя
  строка без перевода.
- `check-rotation.mjs` — дописывание, усечение, замена файла (ротация через rename).
- `check-pool.mjs` — два одновременных `get` получают один `LogFile`, после `release` файл
  открывается заново, отсутствующий путь отклоняется; с `--expose-gc` проверяется, что
  незакрытых `FileHandle` не осталось. Нужна сборка `server/dist`, сервер не нужен.

Ожидаемый результат — 4/4, 4/4 и 5/5 PASS.

### Правила и фильтры

```bash
node scripts/check-rules-semantics.mjs   # чистая семантика, сервер не нужен
node scripts/check-rules.mjs             # API: сохранение, issues, нормализация, панель
node scripts/check-rules-timeout.mjs     # патологический regex (headless Edge)
node scripts/check-filter.mjs            # include-фильтр и автодогрузка (headless Edge)
node scripts/check-panel.mjs             # автосейв из панели и позиция чтения
```

- `check-rules-semantics.mjs` — приоритет, регистр, битый и пустой паттерн, include/exclude.
  Единственная проверка, которой не нужен запущенный сервер.
- `check-rules.mjs` — `PUT /rules` и `PUT /filters` принимают битый regex с `issues`, а не 400;
  цвета нормализуются; панель в `ui` сохраняется и зажимается по ширине.
- `check-rules-timeout.mjs` — правило `(a+)+$` убивается по таймауту, помечается
  `disabledReason: 'timeout'`, остальные правила продолжают красить строки.
- `check-filter.mjs` — include оставляет только совпадения, буфер сам догружается до начала
  файла, счётчики в статусе и в полосе фильтра совпадают.
- `check-panel.mjs` — правило из панели сохраняется автосейвом и переживает перезагрузку;
  `scrollOffset` пишется и восстанавливается на вкладке без tail.

### Поиск по файлу

```bash
node scripts/check-search.mjs      # API: направления, кодировки, таймаут
node scripts/check-search-ui.mjs   # браузер: Enter, F3, догрузка страницы
node scripts/check-search-hits.mjs # браузер: все совпадения в буфере, таймаут подсветки
```

- `check-search.mjs` — 22 проверки: продолжение по курсору вперёд/назад, регистр, regex,
  битый regex и пустой запрос (400), cp1251 и UTF-16LE, `timedOut` на `(a+)+$` и ответ
  `/health` во время зависшего воркера.
- `check-search-ui.mjs` — 9 проверок: `Enter` находит совпадение, `F3`/`Shift+F3` ходят по
  файлу, совпадение вне буфера догружает страницу, флаги поиска переживают reload.
- `check-search-hits.mjs` — 12 проверок: маркеры появляются без `Enter` и только на
  совпавших строках, текущее совпадение помечено, маркеры есть в середине буфера,
  tail-append получает маркер по смещению, очистка их убирает, зависший regex отключает
  подсветку без блокировки UI и восстанавливается после смены запроса.

Ожидаемый результат — 22/22, 9/9 и 12/12 PASS.

### Номера строк

```bash
node scripts/check-lines.mjs      # API: индекс, firstLine, переход, append, усечение, кэш
node scripts/check-lines-ui.mjs   # браузер: `·`, фильтр, Ctrl+G, догрузка, tail
```

- `check-lines.mjs` — 40 проверок: засечки каждые 1024 строки, точные `line-offset` и
  `line-number`, `firstLine` у `page`/`last-page`, достройка после append без пересборки,
  сброс после усечения, cp1251 и UTF-16LE, файл без перевода в конце, пустой файл и
  переиспользование кэша новым экземпляром сервиса.
- `check-lines-ui.mjs` — 16 проверок: без индекса в линейке `·`, под фильтром номера не
  меняются, `Ctrl+G` переходит к строке, «выше» сохраняет нумерацию, строка за концом файла
  даёт сообщение, tail-append получает точный номер, индекс достраивается.

Первый сценарий импортирует `server/dist/files/lineIndex.js`, поэтому перед запуском нужна
сборка (`npm run build`). Ожидаемый результат — 40/40 и 16/16 PASS.

Скрипты с браузером требуют запущенный сервер и Edge; профиль они меняют временно и
восстанавливают в `finally`. Если проверка упала посередине, сверь `profile.json`.
