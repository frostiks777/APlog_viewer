# APlog Viewer — инструкция для AI-агентов

Дашборд для просмотра и анализа логов приложений (AP) одним пользователем: логи читаются
напрямую с сетевых шар, строки подсвечиваются по настраиваемым правилам, поддерживаются
разные кодировки и файлы от 10–30 МБ (часто) до нескольких ГБ (редко). Настройки рабочего
пространства сохраняются между запусками. Референс по функциональности — UVviewsoft LogViewer.

Этот файл — единственный источник правил для агентов в этом репозитории. Долговременная
память между сессиями — `MEMORY.md`; глоссарий предметной области — `CONTEXT.md`;
архитектурные решения — `docs/adr/`. Если правила расходятся с кодом — прав код, правило
надо обновить.

## Команды

```bash
npm ci                # установка строго по lock-файлу
npm run dev           # vite (5173) + fastify (7801) с прокси
npm run build         # сборка web и server
npm start             # production: API и статика на 127.0.0.1:7801
npm run typecheck     # tsc strict для обоих пакетов
npm run shot          # скриншот UI через headless Edge
node scripts/check-encodings.mjs   # кодировки и границы строк (нужен запущенный сервер)
node scripts/check-rotation.mjs    # append/truncate/rotate (нужен запущенный сервер)
node scripts/check-rules.mjs       # правила и фильтры (см. .agents/shared/checks.md)
node scripts/check-search.mjs      # поиск по файлу через API
node scripts/check-search-ui.mjs   # поиск по файлу в браузере (headless Edge)
```

Полный чек-чейн — `.agents/shared/checks.md`; здесь не дублируй его.

## Layout & data flow

- `server/src/index.ts` — Fastify, Host/Origin-allowlist, статика, открытие браузера.
- `server/src/files/reader.ts` — ядро: позиционное чтение окнами, границы строк по
  кодировке, идентичность `dev:ino`, события ротации/усечения.
- `server/src/files/encoding.ts` — BOM и автоопределение кодировки.
- `server/src/files/lines.ts` — общий разбор строк: CRLF, UTF-16, границы и BOM.
- `server/src/search/` — поиск по всему файлу в worker-потоке: курсоры, бюджет 5 с.
- `server/src/api/routes.ts` — REST v1 (вкладки, страницы, поиск, tail, last-page, page-before).
- `server/src/profile/store.ts` — профиль `.aplog/profile.json`, `.bak`, атомарная запись.
- `web/src/App.tsx` — вкладки, виртуализованный список, линейка-точки, поиск, tail.
- `web/src/RulesPanel.tsx` — выдвижная панель правил подсветки и фильтров.
- `web/src/rules/` — компиляция правил, матчинг в Web Worker с бюджетом времени, кэш стилей.
- `web/src/search/useFileSearch.ts` — сессия поиска: кэш совпадений, `F3`/`Shift+F3`, переходы.
- Поток данных: путь из профиля → `LogFilePool` → `readPage`/`readTail` → JSON → React.
  Файл целиком в память не читается никогда.

Перед первой правкой читать: этот файл, `.agents/shared/checks.md`, `docs/adr/0001-log-reading-contract.md`.

## Conventions

- **Комментарии объясняют «почему», а не «что».** Приёмы и формулировки запроса —
  `docs/agents/code-comments.md`. Сгенерированный комментарий — черновик: сверяй с
  `git log`/`blame` и тестами.
- **Язык UI:** все пользовательские строки — русские (EN — только имена технических полей
  и форматов). Код, имена сущностей и коммиты — английские.
- Именование, форматтер и линтер фиксируются вместе со стеком после интервью по задаче 2.

## AI-assisted development cycle

Любая нетривиальная работа (больше одного метода, > ~2 файлов, новый экран, формат данных,
изменение поведения) начинается с файла задачи:
`tasks/<YYYY-MM-DD>-<slug>/task.md` по `tasks/TEMPLATE.md` — скилл `task-file`.
Правка одного метода или опечатка идёт сразу в код без файла.

Внутри задачи процессные скиллы идут по порядку:
`interview → plan → (ponytail) → (tdd) → task-file (evidence) → verify → commit-push`.

- **Одна задача — один PR.** Если работа выросла за рамки критериев — стоп и отдельный
  `task.md`, а не раздувание диффа.
- **Перед коммитом** — прогнать `.agents/shared/checks.md`. Красная проверка от твоего
  диффа означает, что задача не сделана.
- **Коммиты** — Conventional Commits (`feat:`, `fix:`, `chore:`, `docs:`).
- Файл задачи не удаляется после мержа: `Статус: done` — это история решения.

## Agent skills

Скиллы лежат в `.agents/skills/<name>/SKILL.md` и подхватываются по `description` из
frontmatter. Имена директорий должны совпадать с `name`.

- Процессные: `interview`, `plan`, `ponytail`, `tdd`, `verify`, `commit-push`, `task-file`.
- `task-file` — единственный источник правды о задачах проекта (`tasks/`). Скиллы харнесса
  `process-inbox`, `perform-task`, `continue` в этом репозитории не используются.
- Вспомогательные — по триггеру из описания.

Новый скилл: создать `.agents/skills/<name>/SKILL.md` с YAML-frontmatter
(`name` = имя директории, `description` = триггер).

## Hygiene of context window

- **Правило двух итераций:** если одна и та же проверка красная после двух попыток —
  сформулируй, почему подход неверен, предложи альтернативу и спроси владельца.
- Если диалог вырос, а прогресса нет — предложи `/compact` или новую сессию со ссылками
  на `AGENTS.md`, `MEMORY.md`, `CONTEXT.md`, `docs/adr/`.
- Долговременный контекст живёт только в файлах; всё, что не записано, теряется.

## Long-term memory

- `MEMORY.md` — состояние проекта между сессиями: стек, критические фиксы, результаты
  проверок. Обновляй при изменении стека или после крупной работы.
- `CONTEXT.md` — глоссарий предметной области; используй его словарь в issue, коммитах,
  коде и UI.
- `docs/adr/` — по одному ADR на трудно обратимое решение.

## Safety gates

- **Read-only в проде:** если окружение — production/staging, разрешены только чтение и
  диагностика. Никаких записей, миграций и удалений.
- **Human-in-the-loop:** force-push, `git reset --hard`, перезапись `MEMORY.md`, удаление
  ADR, правки CI-воркфлоу и действия на прод-сервере — только по явному запросу владельца;
  сначала покажи команду и последствия.
- **Destructive operations:** `rm -rf`, `rsync --delete`, очистка пользовательских данных —
  сначала dry-run/дифф и подтверждение.
- **Секреты:** токены и пароли не пишутся в код и коммиты; `.env` остаётся gitignored.

## Notifications

Уведомляй владельца только в двух случаях: (1) нужно решение — вопрос, развилка, блокер;
(2) успешный релиз — push прошёл, CI/деплой зелёные, задача закрыта.

Каналы: Windows-тост `powershell.exe -NoProfile -ExecutionPolicy Bypass -File
scripts/notify.ps1 "Заголовок" "Текст"` (сам файл `scripts/notify.ps1` обязан быть UTF-8 с BOM; запускать через `powershell.exe`
5.1, не `pwsh` 7); Telegram — если установлен адаптер `telegram/`.

## Agent behavior

- **Task routing:** нетривиальная работа → `tasks/<YYYY-MM-DD>-<slug>/task.md`
  (скилл `task-file`); правка одного метода или опечатка — сразу в код.
- **Одна задача — одно изменение.** План — это порядок, а не единица работы.
- Не коммить сгенерированный мусор (кэши, state, артефакты сборки и зависимостей).
- Все пользовательские строки — на языке проекта (см. Conventions).
- Перед отметкой «готово» — `verify` и отчёт с фактическим выводом команд.
